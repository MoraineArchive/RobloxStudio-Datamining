# Open Cloud Usage

> **MCP only.** Direct Open Cloud access for agents is only available to external MCP clients, through the `open_cloud_invoke` tool. The guidance in this skill does not apply to the built-in Studio Assistant. If `open_cloud_invoke` is not in your tool list, Open Cloud is not available to you; ask the user to make the change in the Creator Dashboard instead.

Access Open Cloud by calling the `open_cloud_invoke` tool. Do not make Open Cloud requests from Luau scripts.

Studio authenticates each request automatically, using a token limited to the Open Cloud scopes enabled in the MCP Permissions tab of Assistant Settings. Never pass API keys or auth headers yourself.

- `method`: `GET`, `POST`, `PUT`, `PATCH`, or `DELETE`.
- `endpoint`: the path under `https://apis.roblox.com`, starting with `/` and including any query string (e.g., `/cloud/v2/universes/123`). Full URLs are not accepted.
- `body`: a JSON-encoded string. Omit for `GET` and `DELETE`.
- `scopes`: the Open Cloud scopes the endpoint requires (e.g., `["universe:read"]`). Optional, but passing them produces a precise error when a scope has not been enabled.
- `files`: local asset files to upload as multipart/form-data. See the tool description for details.

Example: `open_cloud_invoke(method: "GET", endpoint: "/cloud/v2/universes/123", scopes: ["universe:read"])`

## Data Stores and Memory Stores

Do not access Data Stores or Memory Stores through Open Cloud. Use the standard engine APIs for those features instead (`DataStoreService` and `MemoryStoreService`). Engine API usage respects the scopes configured in MCP Permissions.

## Finding Endpoints

Available Open Cloud APIs are described here: https://create.roblox.com/docs/cloud/llms.txt

Use the `http_get` tool to fetch this URL and read the API listing. Any URLs referenced within the llms.txt response should also be fetched via `http_get` to get the detailed API documentation needed for your request.

## Error Handling

- `Scope '<scope>' has been denied`
  → The scope needs to be enabled in the Assistant Settings dialog's MCP Permissions tab. Ask the user to enable it and retry after they confirm it's enabled. Do not try to work around it.
- HTTP 403
  → The required scope needs to be enabled in the Assistant Settings dialog's MCP Permissions tab. Ask the user to enable it and retry after they confirm it's enabled. Do not try to work around it.
- HTTP 401
  → The token was rejected. Retry the request once; `open_cloud_invoke` requests a fresh token on each call.
- A file is not inside an approved upload directory
  → Ask the user to add the file's directory to the approved upload directories in Assistant Settings → MCP Permissions, then retry. Do not copy or move the file to work around this.
